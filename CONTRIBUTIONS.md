# Open pull requests

Fixes and features waiting for review, with what each one fixes. Merged work is on the [profile page](https://github.com/skybleak333).

## AI and agents

- **MCP PHP SDK:** [#735](https://github.com/modelcontextprotocol/php-sdk/pull/735) a tool with a variadic enum parameter could not be called, [#736](https://github.com/modelcontextprotocol/php-sdk/pull/736) an `iterable` parameter refused JSON arrays, [#737](https://github.com/modelcontextprotocol/php-sdk/pull/737) an unknown method got `-32600` instead of `-32601`, [#738](https://github.com/modelcontextprotocol/php-sdk/pull/738) completion for a resource template answered with another template's values.
- **[google-gemini-php/client](https://github.com/google-gemini-php/client):** [#193](https://github.com/google-gemini-php/client/pull/193) exposes the retry delay and quota details Gemini sends with a 429.
- **[logiscape/mcp-sdk-php](https://github.com/logiscape/mcp-sdk-php)** (community MCP SDK for PHP): [#66](https://github.com/logiscape/mcp-sdk-php/pull/66) a stdio server died on a message that arrived in several reads, e.g. a tool call with a 1 MB argument; [#67](https://github.com/logiscape/mcp-sdk-php/pull/67) one malformed line from the client ended the server. [#68](https://github.com/logiscape/mcp-sdk-php/pull/68) the PHP client failed on a server response of 500 KB or more.
- **[opgginc/laravel-mcp-server](https://github.com/opgginc/laravel-mcp-server)** (MCP servers for Laravel): [#111](https://github.com/opgginc/laravel-mcp-server/pull/111) fixes [#74](https://github.com/opgginc/laravel-mcp-server/issues/74), a tool without parameters was listed with `"properties": []`, which MCP clients such as the Inspector reject; [#112](https://github.com/opgginc/laravel-mcp-server/pull/112) fixes [#66](https://github.com/opgginc/laravel-mcp-server/issues/66), `mcp:test-tool` crashed on a nullable type such as `["integer", "null"]`.
- **[openai-php/client](https://github.com/openai-php/client):** [#844](https://github.com/openai-php/client/pull/844) adds `responses()->inputTokens()->count()`, to count the tokens of a request before sending it. [#845](https://github.com/openai-php/client/pull/845) adds `responses()->compact()`, to compact a long conversation into one encrypted item.
- **[openai-php/laravel](https://github.com/openai-php/laravel):** [#214](https://github.com/openai-php/laravel/pull/214) after `OpenAI::fake()`, a class that got the client injected still sent real requests.
- **[symfony/ai](https://github.com/symfony/ai):** [#2897](https://github.com/symfony/ai/pull/2897) `drop()` on the Neo4j store deleted every node in the database. [#2913](https://github.com/symfony/ai/pull/2913) a rate limited chat completion through the Generic bridge (Groq, OpenRouter, Together) lost the `retry-after` time. [#2923](https://github.com/symfony/ai/pull/2923) a tool parameter typed as an array shape such as `array{name: string}` was described to the model as a list, so the tool got `$person[0]` instead of `$person['name']`. Claude: [#2930](https://github.com/symfony/ai/pull/2930) a run that allowed no tool got a 400 from Anthropic (also on Bedrock); [#2931](https://github.com/symfony/ai/pull/2931) a text or Markdown document was sent as a source Anthropic takes for PDF only; [#2932](https://github.com/symfony/ai/pull/2932) an empty text block Claude sometimes returns made the next request of a tool loop fail. Vector stores: [#2918](https://github.com/symfony/ai/pull/2918) `drop()` on a cache store emptied the whole cache pool, `cache.app` by default; [#2919](https://github.com/symfony/ai/pull/2919) Chroma results came back without their text, so RAG answers got no content; [#2920](https://github.com/symfony/ai/pull/2920) Milvus `drop()` dropped a database and left the collection, and [#2925](https://github.com/symfony/ai/pull/2925) its metadata field held 512 bytes, too little for the text of a normal chunk; [#2921](https://github.com/symfony/ai/pull/2921) Weaviate dropped documents that failed in a batch without an error; [#2922](https://github.com/symfony/ai/pull/2922) Azure AI Search put each hit's embedding into what the model gets; [#2924](https://github.com/symfony/ai/pull/2924) S3 Vectors `drop()` also deleted the bucket, which failed while other stores kept their indexes there; [#2926](https://github.com/symfony/ai/pull/2926) the Vektor store worked only in the process that ran `setup()`, elsewhere it wrote into `vendor/` with the wrong dimensions.
- **[Prism](https://github.com/prism-php/prism):** [#1054](https://github.com/prism-php/prism/pull/1054) fixes [#990](https://github.com/prism-php/prism/issues/990), DeepSeek and Perplexity streams arrived all at once and failed after 30 s; [#1055](https://github.com/prism-php/prism/pull/1055) a Laravel MCP tool with a dependency in `handle()` failed, and the model was told its arguments were missing; [#1056](https://github.com/prism-php/prism/pull/1056) OpenAI and Groq rate limits lost or misread their reset time: `6m0s`, the example in OpenAI's docs, gave none, and Groq's `13h22m10s` became 13 minutes. [#1057](https://github.com/prism-php/prism/pull/1057) fixes [#948](https://github.com/prism-php/prism/issues/948), a text query to a Voyage multimodal model went to the text endpoint and got a 400. [#1058](https://github.com/prism-php/prism/pull/1058) Mistral rate limits read headers Mistral no longer sends, so every response reported 0 tokens left. [#1059](https://github.com/prism-php/prism/pull/1059) with Ollama streaming, only the last of several tool calls in a step ran; [#1060](https://github.com/prism-php/prism/pull/1060) a code interpreter answer that wrote a file failed after OpenAI had run and billed it; [#1061](https://github.com/prism-php/prism/pull/1061) a Mistral validation error became a PHP `TypeError`; [#1062](https://github.com/prism-php/prism/pull/1062) a Gemini stream cut off by an error ended as a normal answer; [#1063](https://github.com/prism-php/prism/pull/1063) Perplexity never got the system prompt; [#1064](https://github.com/prism-php/prism/pull/1064) DeepSeek structured output ignored the token limit; [#1065](https://github.com/prism-php/prism/pull/1065) ElevenLabs text to speech used its default model whatever model was asked for; [#1066](https://github.com/prism-php/prism/pull/1066) a streamed DeepSeek request with tools failed after the first tool call, as the reasoning DeepSeek requires back was dropped.
- **[LLPhant](https://github.com/LLPhant/LLPhant):** [#569](https://github.com/LLPhant/LLPhant/pull/569) a tool that returned nothing next to another tool call made OpenAI reject the follow-up with a 400.
- **Hindsight** (issues with failing tests and patches): [#6444](https://github.com/vectorize-io/hindsight/issues/6444), [#6450](https://github.com/vectorize-io/hindsight/issues/6450), [#6452](https://github.com/vectorize-io/hindsight/issues/6452).

## Backend infrastructure

- **[Symfony](https://github.com/symfony/symfony):** [#68130](https://github.com/symfony/symfony/pull/68130) in HttpClient: when a streamed POST lost its connection, `EventSourceHttpClient` silently sent it again, so a Symfony AI chat completion was generated and billed twice ([symfony/ai#2898](https://github.com/symfony/ai/issues/2898)). [#68131](https://github.com/symfony/symfony/pull/68131) the SSE parser gave an empty `event:` the type `''` instead of `message`, and dropped an empty first `data:` line. [#68133](https://github.com/symfony/symfony/pull/68133) in the new JsonSchema component, which describes tool inputs and structured outputs to AI agents: with extra attributes not allowed, the objects created by a `#[SerializedPath]` stayed open, so OpenAI strict mode refused the schema.
- **[Spatie](https://github.com/spatie)**: [laravel-query-builder#1076](https://github.com/spatie/laravel-query-builder/pull/1076), `->ignore(null)`, the example in its docs, dropped `filter[active]=false`, so the query returned every record; [laravel-sluggable#320](https://github.com/spatie/laravel-sluggable/pull/320), with self-healing URLs a route that named its column, such as `{post:id}`, returned 404; [laravel-activitylog#1481](https://github.com/spatie/laravel-activitylog/pull/1481), with buffering on, an activity model without an `updated_at` column lost every buffered activity of the request; [laravel-settings#371](https://github.com/spatie/laravel-settings/pull/371), settings with a `DateTimeInterface` or `CarbonInterface` property failed to load.
- **[Monolog](https://github.com/Seldaek/monolog)**: [#2095](https://github.com/Seldaek/monolog/pull/2095), `HtmlFormatter` dropped any message or context that was not valid UTF-8, so the error emails of `MailHandler` came without the message; [#2096](https://github.com/Seldaek/monolog/pull/2096), hourly log files named like `YmdH` still rotated only at midnight; [#2097](https://github.com/Seldaek/monolog/pull/2097), `PsrLogMessageProcessor` ignored its date format for Monolog and Carbon dates.
- **[php-amqplib#1248](https://github.com/php-amqplib/php-amqplib/pull/1248)**: fixes [#1227](https://github.com/php-amqplib/php-amqplib/issues/1227) in the main PHP AMQP client. The heartbeat check counted the client's own writes, so a consumer whose network dropped never noticed. Reproduced with toxiproxy; opt-in, so proxies that send heartbeats differently (AMQProxy before 3.2.1) aren't affected. [#1249](https://github.com/php-amqplib/php-amqplib/pull/1249) fixes [#1243](https://github.com/php-amqplib/php-amqplib/issues/1243): the error handler around socket calls turned unrelated deprecations into exceptions. In the async client [bunny](https://github.com/jakubkulhan/bunny), [#237](https://github.com/jakubkulhan/bunny/pull/237): after one failed connect, every later `channel()` call hung forever.
- **[vyuldashev/laravel-queue-rabbitmq#680](https://github.com/vyuldashev/laravel-queue-rabbitmq/pull/680)**: fixes `rabbitmq:consume` for the Worker API changes in Laravel 11.52+, 12.59+ and 13.x. With the released v15.0.2 it doesn't process jobs on Laravel 13.31+. [#684](https://github.com/vyuldashev/laravel-queue-rabbitmq/pull/684) builds on it: in maintenance mode a paused `rabbitmq:consume` ignored SIGTERM, `queue:restart` and `--max-time`.
